# Themes and dark mode

## Excalidraw's dark mode is a filter, not a palette

Excalidraw stores no dark palette. It renders dark mode by applying

```text
DARK_THEME_FILTER = invert(93%) hue-rotate(180deg)
```

as a CSS filter on the interactive canvas, and mathematically via `applyDarkModeFilter()` to
element colours on the static canvas. The invert is 93% rather than 100% so that white lands on
a dark grey (`#ffffff` becomes `#121212`) instead of pure black. `hue-rotate(180deg)` undoes the
hue flip that inversion causes, so hues survive and only lightness reverses. Each row of the
matrix sums to `1.0`, which is why greys stay grey.

Three consequences:

1. **Never author two palettes for one diagram.** A "dark version" is the same file with
   `appState.theme` set to `dark`.
2. **A curated palette will not survive the filter.** Run Dracula's colours through it and you
   get a light diagram in un-Dracula colours. This is why the bundled themes are _baked_.
3. **Never embed bitmap images.** Excalidraw counter-filters them with
   `invert(100%) hue-rotate(180deg) saturate(1.25)` — explicitly a temporary hack upstream — and
   double-inverted images come back desaturated. Use vector elements.

## Baked themes

Every theme in `themes/` sets `"authored": "baked"`, meaning:

- Colours are written literally into each element.
- `appState.theme` stays `"light"` so the inversion filter never runs.
- `appState.viewBackgroundColor` is set to the theme's canvas colour.

A dark baked theme therefore produces a genuinely dark diagram with exact colour fidelity — a
Tokyo Night diagram is Tokyo Night, pixel for pixel, on every Excalidraw build.

**The tradeoff:** if you then toggle Excalidraw's own dark mode in the app, a dark-baked diagram
gets inverted into a light one. Baked-dark diagrams are meant to be viewed with the app theme set
to light. `scripts/check-theme.mjs` fails any diagram that ships `appState.theme: "dark"`
alongside baked colours.

## Theme structure

```json
{
  "id": "tokyo-night",
  "mode": "dark",
  "authored": "baked",
  "canvas": { "background": "#1a1b26", "panel": "#292e42" },
  "ink": { "primary": "#c0caf5", "muted": "#7982a9", "connector": "#7aa2f7" },
  "surfaces": [
    {
      "slot": "blue",
      "fill": "#2b334c",
      "stroke": "#7aa2f7",
      "text": "#c0caf5",
      "contrast": 7.74
    }
  ],
  "defaults": {
    "roughness": 1,
    "strokeWidth": 2,
    "fontFamily": 5,
    "fontSize": 20
  }
}
```

`surfaces` always holds six entries in a fixed slot order — `blue`, `green`, `amber`, `red`,
`violet`, `teal` — so "category 3" means the same position in every theme and swapping themes
never reshuffles which node is which colour.

Surface fills are generated by mixing the accent into the canvas colour: 18% for dark themes
(keeps shapes dark and lets the accent live in the stroke) and 20% for light themes (the familiar
Excalidraw pastel). Every `text`-on-`fill` pair clears WCAG AA at 4.5:1; the worst across all
bundled themes is 6.61.

## Available themes

| Theme                | Mode  | Notes                                                        |
| -------------------- | ----- | ------------------------------------------------------------ |
| `tokyo-night`        | dark  | Default. Cool blues and violets, low glare.                  |
| `catppuccin-mocha`   | dark  | Soft pastel accents on a warm-neutral base.                  |
| `dracula`            | dark  | High-saturation accents, strongest contrast of the dark set. |
| `nord`               | dark  | Desaturated arctic palette; calmest option.                  |
| `one-dark-pro`       | dark  | Familiar editor greys.                                       |
| `gruvbox-dark`       | dark  | Warm retro; good for print-adjacent work.                    |
| `monokai`            | dark  | Vivid pink/green; best for small diagrams.                   |
| `synthwave-84`       | dark  | Neon on deep purple. Use sparingly.                          |
| `github-light`       | light | Safest for docs, slides, and printing.                       |
| `solarized-light`    | light | Warm paper base, low glare.                                  |
| `excalidraw-classic` | light | Excalidraw's own defaults.                                   |

Default to `tokyo-night` unless the diagram is destined for a light document or print, in which
case use `github-light`.

## Previewing the filter

To see what a _light_ theme becomes under Excalidraw's dark mode:

```bash
node scripts/render.mjs diagram.excalidraw --both
```

This writes `diagram.png` and `diagram.dark.png`. The dark render is produced by applying the
real filter maths to the colours (`scripts/dark-filter.mjs`) and rendering the result — the
external exporter does not implement dark mode itself, and left to its own devices it will
happily render light-coloured shapes on a dark background and call it dark mode.

## Validating

```bash
node scripts/check-theme.mjs                                   # all themes
node scripts/check-theme.mjs --theme tokyo-night diagram.excalidraw   # diagram conformance
```

The diagram check fails on off-theme colours, a mismatched `viewBackgroundColor`, or
`appState.theme: "dark"`.

Three light themes emit warnings because an accent stroke sits just under 3.0:1 against the
canvas — Excalidraw's own amber at 2.48, and three Solarized accents between 2.93 and 2.98.
These are the authentic upstream values and are deliberately left unmodified; strokes are
decorative here and every text pair still clears AA. Do not "fix" them, or they stop being
Solarized.
